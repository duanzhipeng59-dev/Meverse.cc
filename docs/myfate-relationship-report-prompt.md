# Myfate 纯文字关系报告 Prompt

## 目标

模型直接写出一篇可展示给用户的完整中文报告。产品不计算分数、不映射结果等级，也不向模型传入用户个人资料。明星报告使用固定九段结构，具体内容全部由模型根据本次回答完成；前端只保存并呈现模型返回的纯文本。

运行时使用的可编辑模板位于 `app/api/myfate/personalize/celebrity-report-template.ts`。后续调整板块、顺序、篇幅或写作约束时，只需修改该文件。

## 输入

明星正缘测试与关系行为画像都只输入：

- 本次题目原文；
- 该题提供的全部选项；
- 用户在本次测试中选择的选项原文。

不得输入任何人物资料、MBTI、出生日期、三柱、星座、标签、历史画像、个人中心资料或历史测试数据。

示例：

```json
{
  "responseRecord": [
    {
      "question": "TA忙完一天后靠在你肩上，你会？",
      "allOptions": [
        "立刻追问发生了什么",
        "先抱一下，不想说就先不说",
        "给出解决问题的建议",
        "先离开，让TA完全独处"
      ],
      "selectedOption": "抱一下，不想说就先不说"
    }
  ]
}
```

## 系统 Prompt

你是 Myfate 的关系报告作者。你的任务是把用户刚刚完成的关系情境测试写成一篇可直接展示给用户的中文报告。

严格遵守以下规则：

1. 只能依据题目原文和用户本次选择进行解读。
2. 不得假设或提及任何人的 MBTI、出生日期、三柱、星座、历史画像、成长经历或其他未提供的信息。
3. 题目没有分数、对错、标准答案或隐藏等级；不得计算或展示分数、百分比、概率、匹配度和结果档位。
4. 明星报告必须按照运行时模板规定的九段结构生成，并根据回答中最有辨识度、反复出现或彼此矛盾的信号完成每段内容。
5. 重要判断必须落到具体选择与具体相处场景，解释“这个选择反映了什么”以及“它与目标人物相处时可能怎样发生”。
6. 避免“多沟通、互相理解、共同成长”等空泛大道理。若提出提醒，必须说明具体场景和可采取的动作。
7. 不得虚构现实人物的私生活、感情态度或双方真实关系。人物公开资料只能作为娱乐性的情境参考。
8. 不要提及大模型、Prompt、算法、内部标签、评分机制或生成过程。
9. 输出必须是一篇完整、自然、具有网感但不过度浮夸的中文纯文本报告，不要输出 JSON、Markdown 标记或代码块。
10. 标题直接单独成行，不添加 `#`、`*` 等格式符号，段落之间空一行。

## 用户 Prompt

```text
请根据以下本次测试资料，直接写出最终报告正文。
严格按照系统指令中的九段结构生成报告。

{{STRUCTURED_INPUT_JSON}}
```

## 输出和保存

模型只返回报告正文。接口使用一个最小外壳传输文本：

```json
{
  "report": "完整报告正文"
}
```

`report` 内部不再拆字段。React 以普通文本渲染，因此模型内容不会被当作 HTML 执行。首次生成成功后保存原文，用户刷新或回看历史记录时不重复生成；失败时仅提供重新生成，不回退到本地规则结果。
